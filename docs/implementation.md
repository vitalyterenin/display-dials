# Реализация и следующие шаги

## Цель MVP

Встроенный XDR-экран MacBook Pro. Два независимых регулятора: буст яркости и теплота.
Без исключений для приложений и без полного набора инструментов BetterDisplay.
Рабочее название: Display Dials. Тексты интерфейса собраны вокруг AppIdentity;
при переименовании также обновить Package.swift, bundle metadata и путь bundle.

## Компоненты

- `DisplayDials`: AppKit status item, popover и диагностический режим.
- `NightShiftBridge`: собственный Objective-C адаптер к private CoreBrightness.
  Проверяет типы аргументов, размер и выравнивание структуры статуса; этот контроль
  не заменяет проверки поведения на каждой поддерживаемой macOS.
- `DisplayCore`: чистая политика ограничений буста, без обращения к железу.
- `DisplayCoreTests`: ограничения headroom, температуры, NaN/Infinity, сна и экранов.

Приложение не переустанавливает Night Shift на старте, не меняет его расписание
и не перезаписывает настройки при выходе. Уровень теплоты — относительные 0–100%,
не заявленная цветовая температура в K. Состояние перечитывается при открытии панели
и каждые две секунды, пока панель видна.

## Буст: ещё не реализован

Проверить EDR-композицию на Metal/CAMetalLayer в отдельном прототипе. Публичное
свойство `wantsExtendedDynamicRangeContent` разрешает приложению HDR-контент,
но само по себе не предоставляет публичный API усиления всего рабочего стола.
Не копировать стороннюю реализацию; отдельно оценить применимость композиции.

Политика сейчас блокирует любой невалидированный renderer и не вызывает никаких
функций изменения яркости. Потолок 1.25 в политике — гипотеза для будущего
эксперимента, а не измеренный безопасный коэффициент или обещание 125% нит.

Перед подключением renderer к переключателю:

1. Убедиться, что усиление реально действует на рабочий стол и не портит цвет,
   контраст, HDR-контент, скриншоты и полноэкранные Spaces.
2. Ограничивать выход текущим headroom; потенциальный headroom не использовать
   как разрешение на вывод. Не обходить снижение яркости, выполняемое macOS.
3. При любой температурной категории выше nominal — отключать усиление.
   `ProcessInfo.thermalState` отражает нагрузку системы, не температуру панели.
4. Убирать эффект при сне, блокировке сессии, выходе и изменении экрана;
   после пробуждения требовать нового явного включения. При нехватке headroom
   не повышать яркость автоматически после его восстановления.
5. Проверить нормальный выход, аварийное завершение, потерю GPU-контекста и
   перезапуск. Обычный экран должен восстанавливаться без запуска приложения.
6. Проверить совместимость с Night Shift и обнаружение активных утилит усиления.
7. До заявления о длительном режиме провести наблюдения за нагревом и поведением
   дисплея. Не утверждать, что отсутствие видимых проблем доказывает нулевой износ.

Это этапы разработки, а не запрос новых подтверждений на уже согласованную работу.

## Проверка первого прототипа

На Apple Silicon с macOS 27.2 и Command Line Tools / Swift 6.4.2:

- 5 тестов политики ограничений пройдены.
- Release bundle собирается и проходит `codesign --verify --strict`.
- Диагностика обнаружила встроенный экран и успешно прочитала состояние Night Shift.
- Smoke test создаёт интерфейс и завершается; чтения Night Shift до и после совпали.
- Проверен PNG-рендер реального AppKit view через `--smoke-test --snapshot <path>`.

Переключение Night Shift и ползунок не проверялись изменением пользовательских
настроек. Ручная проверка работы панели из строки меню остаётся нужна: автоматизация
нативного приложения завершалась тайм-аутом, поэтому для проверки компоновки
использован рендер view. На других версиях macOS приложение ещё не проверено.
